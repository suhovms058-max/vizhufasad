# Выбор provider для Stage 12

Дата проверки документации: 22 августа 2026 года. Область решения: Pro-генерация фасада,
текстовые и масочные доработки и настоящий 4K-upscale. Все функции остаются выключенными до
практического теста на закрытых фотографиях фасадов.

## Предварительное решение

| Действие | Основной кандидат | Резерв | Документированная возможность | Опубликованная цена | Измерено на фасадах |
|---|---|---|---|---:|---|
| Pro | GenAPI `nano-banana-pro` | `seedream-v5-pro` | image edit, входные изображения, 2K | 37,50 ₽ за 1K/2K | Nano Pro — ещё нет |
| Текстовая/областная правка | `qwen-image-edit-plus` | `seedream-v5-pro` | специализированный image edit по тексту | 7,50 ₽/Мп | ещё нет |
| Пользовательская маска | `bria-genfill` | отсутствует до подтверждения | отдельные обязательные поля `image` и `mask` | 12 ₽ | ещё нет |
| 4K | `drct-super-resolution` | `seedvr2` | отдельный upscale 2–4× | уточняется по фактическому API-ответу | ещё нет |

`nano-banana-pro` выбран только как кандидат Pro: документация обещает более высокое качество и
2K, но это не считается доказательством качества фасада. Поэтому `FEATURE_PRO_GENERATION_ENABLED`
остаётся `false`. `seedream-v5-pro` уже измерялся на одном фасаде в Stage 7: 146,26 секунды,
16,88 ₽, геометрия сохранилась, но материальная композиция была слабее Standard Nano Banana 2.
Это измерение делает Seedream полезным контрольным вариантом, но не доказывает превосходство Pro.

## Почему маска отделена от обычного edit

У Nano Banana Pro, Seedream V5 Pro и Qwen Image Edit Plus в опубликованных параметрах есть
входные изображения, но нет отдельного параметра маски. Передавать PNG-маску как второй референс
и называть это гарантированным masked edit некорректно. Для `custom_mask` код допускает только
provider `bria-genfill`, у которого API отдельно требует `image` и `mask`. Остальные области
(`walls`, `plinth`, `roof`, `entrance`, `full_facade`) маршрутизируются в текстовый edit-provider.

## Практический gate перед включением

Нужен новый явно утверждённый денежный лимит. Минимальный тестовый пакет:

1. Два одинаковых Pro-запроса: Nano Banana Pro и Seedream V5 Pro на одном исходнике.
2. Одна текстовая правка Qwen на уже проверенном результате.
3. Одна правка Bria с контрастной PNG-маской; пиксели вне маски сравниваются отдельно.
4. Один DRCT-upscale; проверяются фактические размеры не ниже 3840×2160 либо портретный эквивалент,
   пропорции и артефакты.

Для каждого запроса фиксируются `request_id`, model, prompt version, wall time, provider runtime,
фактическая стоимость, размеры результата и решение существующего quality control. Только после
успеха соответствующий feature flag можно включить.

Подготовленная команда `npm run smoke:stage12:providers` по умолчанию заблокирована: она требует
`GENERATION_LIVE_SMOKE_ENABLED=true`, явный список `STAGE12_SMOKE_ACTIONS`, три приватных пути и
отдельный `STAGE12_SMOKE_BUDGET_MINOR`. После отправки она сразу сохраняет `request_id` в
`metrics.json`; повторный запуск продолжает polling той же уже оплачиваемой задачи, а не создаёт
дубликат.

## Стоимость и договорные ограничения

Опубликованные цены используются лишь как предварительный предел. Источник истины после теста —
фактический `cost` в ответе GenAPI. Карточки GenAPI помечают рассматриваемые модели как пригодные
для коммерческих задач, а страница Bria заявляет использование лицензированных данных, но это не
заменяет проверку договора GenAPI и условий upstream-модели владельцем перед production-запуском.
