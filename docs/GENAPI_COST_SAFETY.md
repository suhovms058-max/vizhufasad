# Защита от повторного списания GenAPI

## Риск

GenAPI может списывать стоимость в момент начала генерации. Разрыв соединения, перезапуск worker или ошибка скачивания результата после этого не означают, что нужно отправлять новый запрос.

## Реализованная защита

- `request_id` сохраняется сразу после принятия запроса GenAPI.
- После перезапуска worker продолжает опрашивать тот же `request_id`, а не создаёт новую генерацию.
- Резервный provider не запускается после того, как основной provider уже принял платный запрос.
- Пользователь может отменить только задачу, которая ещё ждёт в локальной очереди и не имеет `provider_request_id`.
- Если `request_id` не удалось надёжно записать после трёх попыток, задача завершается с возвратом внутреннего кредита без автоматического второго платного запроса.
- Стоимость неуспешного запроса сохраняется, если GenAPI вернул поле `cost`.
- Внутренняя метрика показывает принятые запросы без полученной стоимости для сверки с кабинетом GenAPI.

## Почему нельзя обещать отмену после старта

В актуальной публичной документации GenAPI описаны создание запроса и получение результата по `request_id`, но отдельный endpoint отмены принятой генерации не опубликован. Поэтому после передачи запроса внешнему provider кнопка отмены скрывается, а сервис продолжает получать уже оплаченный результат.

## Следующее улучшение

Для production рекомендуется добавить подписанный webhook GenAPI как резерв к polling. Он уменьшит риск потерять готовый результат при длительной сетевой недоступности, но не заменяет сохранение `request_id` и идемпотентность.
