# Этап 4: проекты и безопасные исходные фотографии

## Граница этапа

Этап отделяет пользовательский проект дома от старой заявки. Авторизация и инфраструктура этапов 2–3
переиспользуются. Генерация фасада, очередь генераций, платежи и настройки фасада здесь не запускаются.

## Пользовательский путь

1. Авторизованный пользователь открывает `/app/new`.
2. API создаёт `projects` со статусом `draft`.
3. API создаёт `source_images` со статусом `uploading` и выдаёт presigned PUT URL на 10 минут.
4. Браузер отправляет файл напрямую в приватный S3/MinIO, не проксируя до 25 МБ через Express.
5. После подтверждения API сверяет размер объекта, считывает его с жёстким лимитом и переводит статус
   через `uploaded` и `processing`.
6. Сервер проверяет magic bytes и фактическое декодирование, число пикселей и минимальный размер,
   применяет EXIF-ориентацию, переводит изображение в sRGB и перекодирует его без EXIF.
7. В приватном бакете сохраняются `source.jpg`, `working.jpg` и `thumbnail.webp`; временный карантинный
   объект удаляется. Запись получает статус `ready`, проект — `photo_ready`.
8. При ошибке временные объекты удаляются, изображение получает `invalid`, а проект —
   `photo_retake_required`.

## Форматы и ограничения

- JPG/JPEG, PNG и WEBP;
- HEIC/HEIF отображаются как допустимые только если сборка Sharp подтверждает буферный HEIF-декодер;
  иначе API возвращает `HEIF_CONVERSION_REQUIRED` и UI просит конвертировать файл в JPG;
- максимум 25 МБ;
- максимум 80 000 000 входных пикселей;
- минимум 640×420 независимо от ориентации;
- от 1200×800 помечается как рекомендуемый размер.

Расширение имени и клиентский `Content-Type` не считаются доказательством типа. Итоговый MIME определяется
по сигнатуре, подтверждается декодером и сопоставляется с заявленным типом.

## Доступ и хранение

- Каждая операция с проектом и изображением использует `user_id` действующей серверной сессии.
- Чужой проект и чужое изображение возвращаются как `404`, без раскрытия факта существования.
- Бакет остаётся приватным. URL загрузки и скачивания временные; постоянные публичные URL не создаются.
- PostgreSQL хранит статусы, размеры, MIME, SHA-256 и ключи объектов. Сами изображения в PostgreSQL
  и локальную файловую систему не записываются.
- При успешной замене предыдущие объекты изображения удаляются.
- При удалении проекта его объекты удаляются сразу, а метаданные проекта мягко удаляются и хранятся
  по умолчанию 30 дней.
- `npm run cleanup:images` помечает незавершённые загрузки старше 24 часов недействительными, удаляет их
  объекты и физически удаляет метаданные проектов после retention-периода.
- Метаданные отклонённого изображения сохраняются внутри существующего проекта для диагностики,
  но его загруженный объект удаляется.

Параметры: `S3_UPLOAD_URL_TTL_SECONDS`, `S3_SIGNED_URL_TTL_SECONDS`,
`IMAGE_UPLOAD_CLEANUP_HOURS`, `PROJECT_DELETION_RETENTION_DAYS`, `S3_CORS_ORIGINS`.

## API

- `GET /api/projects`
- `POST /api/projects`
- `GET /api/projects/:projectId`
- `PATCH /api/projects/:projectId`
- `DELETE /api/projects/:projectId`
- `POST /api/projects/:projectId/images/upload-intent`
- `POST /api/projects/:projectId/images/:imageId/complete`
- `GET /api/projects/:projectId/images/:imageId/url?variant=source|working|thumbnail`

## Переход со старых заявок

`POST /api/leads` не удалён и по умолчанию работает в режиме `LEGACY_LEADS_MODE=deprecated`. Ответы содержат
`Deprecation`, `Warning` и ссылку на `/app/new`; при необходимости задаётся `LEGACY_LEADS_SUNSET`.
После отдельной проверки production-пути владелец может задать `LEGACY_LEADS_MODE=disabled`, получив `410`.
Это не удаляет старые JSON и фотографии. Их существующий dry-run/apply скрипт миграции остаётся отдельной
контролируемой процедурой.

## Эксплуатация

Для локального MinIO browser CORS задаётся `MINIO_API_CORS_ALLOW_ORIGIN` из `S3_CORS_ORIGINS`.
Для совместимых облачных S3 сервисов API пытается применить bucket CORS. Origin должен быть точным,
без `*`. В production presigned и session URL должны использовать HTTPS.

Рекомендуемое расписание:

```cron
17 * * * * cd /path/to/vizhufasad/server && npm run cleanup:images
```
